# Library - консольная система учёта библиотеки

Консольное приложение на Java для учёта изданий и читателей библиотеки: выдача и возврат книг и журналов, поиск, сортировка, статистика и сохранение данных между запусками.

> Учебный проект, созданный в процессе изучения Java Core.

## Возможности

- **Издания**: добавление книг и журналов, просмотр списка, поиск по названию и по части названия (без учёта регистра)
- **Читатели**: регистрация с выдачей номера читательского билета, удаление (только если на руках нет изданий)
- **Выдача и возврат**: по номеру или по названию издания, лимит — не больше 3 изданий на руках
    - при выдаче по названию автоматически выбирается свободный экземпляр
    - при возврате по названию поиск идёт среди изданий самого читателя
- **Сортировка**: по номеру, по названию, сначала свободные
- **Сводка по экземплярам**: сколько экземпляров каждого издания и какие из них свободны
- **Статистика**: всего изданий, сколько выдано, разбивка по типам, самый активный читатель, читатели без изданий
- **Сохранение**: данные записываются в файлы при выходе и загружаются при следующем запуске
- **Устойчивость к ошибкам**: некорректный ввод и повреждённые строки в файлах не приводят к падению программы

## Технологии и приёмы

- **Java 25**
- **ООП**: абстрактный класс `LibraryItem` с наследниками `Book` и `Magazine`, полиморфизм (`toString`, `getLoanDays`, `convertToCSV`), инкапсуляция состояния (`markIssued` / `markReturned` вместо сеттеров)
- **Исключения**: собственная иерархия с общим родителем `LibraryException`, валидация данных в конструкторах
- **Коллекции**: `List`, `Map`, `LinkedHashMap`, `TreeMap`, `equals` / `hashCode` по неизменяемому `id`
- **Stream API и лямбды**: `filter`, `map`, `flatMap`, `groupingBy`, `Optional`, ссылки на методы, цепочки компараторов
- **Паттерн «Стратегия»**: поведение передаётся параметром
    - `getItemsSorted(Comparator)` — способ сортировки
    - `findItems(Predicate)` — условие поиска
    - `chooseItem(..., Function)` — способ поиска издания по названию
    - `loadFile(..., Consumer)` — разбор строки файла
- **Работа с файлами**: `java.nio.file`, формат CSV
- **Обобщённые методы**: универсальный вывод списков любого типа

## Структура проекта

```
src/
├── model/        сущности: LibraryItem, Book, Magazine, Reader
├── service/      бизнес-логика: Library
├── ui/           консольное меню: ConsoleMenu
├── storage/      сохранение и загрузка: LibraryStorage
├── exceptions/   собственные исключения
├── testdata/     тестовые данные для первого запуска
└── Main.java     точка входа
```

Слои разделены: `Library` не работает с консолью и файлами, `ConsoleMenu` не знает о файлах, `LibraryStorage` не знает о меню.

## Как запустить

**Требования:** JDK 25 или новее (используются проверки аргументов до вызова `super(...)` в конструкторах).

1. Клонировать репозиторий:
   ```
   git clone https://github.com/VladElizarov/library.git
   ```
2. Открыть папку проекта в IntelliJ IDEA
3. Запустить `Main.java`

При первом запуске загружаются тестовые данные. После выхода из программы через пункт меню `0` появится папка `data` с сохранёнными данными.

## Хранение данных

Данные хранятся в папке `data` в трёх CSV-файлах:

| Файл | Содержимое | Пример строки |
|---|---|---|
| `items.csv` | издания | `Book;0;Война и мир;Лев Толстой;1300` |
| `readers.csv` | читатели | `1;Мария Сидорова` |
| `loans.csv` | выдачи (кто что взял) | `1;2` |

Доступность изданий не хранится отдельно, а восстанавливается по файлу выдач — так данные не могут противоречить друг другу.

Если в файле встречается повреждённая строка (не хватает полей, текст вместо числа, неизвестный тип), она пропускается, а программа выводит предупреждение с именем файла и номером строки:

```
Предупреждение: items.csv, строка 16: Поле количество страниц должно быть числом, получено: abc
```
